# Інструкції з валідації ToDo Web Application на Kubernetes (Helm)

Цей документ містить кроки для валідації розгорнутого Django ToDo Web Application в Kind кластері за допомогою Helm чартів.

## Передумови

Перед виконанням цих інструкцій переконайтеся, що ви виконали всі кроки з `bootstrap.sh` та успішно розгорнули Helm чарт.

## 1. Перевірка стану компонентів кластера

Переконайтеся, що всі Pods, Deployments, StatefulSets та Services працюють належним чином.



3. Перевірка функціональності додатку
Домашня сторінка: Переконайтеся, що домашня сторінка додатку завантажується без помилок.

Реєстрація/Вхід: Спробуйте зареєструвати нового користувача та увійти до системи.

Створення списків/завдань: Створіть новий список завдань та додайте до нього кілька елементів.

Зміна статусу/Видалення: Спробуйте змінити статус завдання (наприклад, "виконано") та видалити його.

API: Спробуйте перейти на сторінку API (зазвичай /api/) і перевірити, чи доступні ендпоінти.

4. Перевірка ресурсів та масштабування (HPA)
Якщо ви ввімкнули HPA (hpa.enabled: true у values.yaml), ви можете спостерігати за його роботою.

Перевірка HPA:

Bash

kubectl get hpa -n todoapp-prod
Ви повинні побачити інформацію про todoapp-todoapp-hpa.

Генерація навантаження (опціонально):
Ви можете генерувати навантаження на Pod додатку, щоб побачити, як HPA збільшує кількість реплік. Наприклад, за допомогою hey або ab:

Bash

# Встановіть hey, якщо його немає: go install [github.com/rakyll/hey@latest](https://github.com/rakyll/hey@latest)
hey -z 1m -c 50 http://localhost:8000/ # Якщо використовуєте port-forward
# Або, якщо через Ingress:
hey -z 1m -c 50 http://localhost/
Спостерігайте за кількістю Pods:

Bash

watch kubectl get pods -n todoapp-prod
Ви повинні побачити, як кількість Pods збільшується, а потім зменшується після припинення навантаження (це може зайняти кілька хвилин).

5. Очищення (опціонально)
